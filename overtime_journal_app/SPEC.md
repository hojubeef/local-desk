# 야근일지 — 프로젝트 스펙

이 문서는 AI가 이 프로젝트에서 작업할 때 먼저 읽어야 할 규칙과 맥락입니다.
`overtime_journal_app` 폴더를 Local Desk/KOSIS 프로젝트에서 분리해 단독으로 관리할 수 있도록 작성했습니다.

---

## 1. AI 작업 원칙

**기존 데이터를 최우선으로 보호한다.**
- 야근일지 JSON, 백업, 휴지통, 결재 상태 파일의 호환성을 깨뜨리지 않는다.
- 저장 구조를 바꿔야 하면 기존 파일을 읽을 수 있는 마이그레이션 방식을 먼저 제안한다.
- 삭제 기능은 반드시 휴지통 또는 백업 흐름을 고려한다.

**추측하지 않고 확인한다.**
- 출퇴근 기록 형식, 직원명 파싱, 공유 드라이브 경로처럼 회사 환경에 의존하는 부분은 코드와 예시 파일을 확인한 뒤 수정한다.
- 애매하면 사용자의 확인을 받는다.

**단독 앱 구조를 유지한다.**
- 이 앱은 포털에 끼워 넣는 페이지가 아니라 Windows에서 EXE로 실행하는 단독 프로그램이다.
- Local Desk, KOSIS, portal 코드에 의존하지 않도록 유지한다.
- 외부 서버 없이 `127.0.0.1` 로컬 서버와 브라우저 화면으로 동작한다.

**UI는 실무자가 바로 쓰기 쉽게 만든다.**
- 입력, 수정, 삭제, 결재, 백업 같은 중요한 버튼은 구분되게 표시한다.
- 직원용 흐름과 관리자용 흐름이 섞여 복잡해지지 않도록 탭 구조를 유지한다.
- 화면 설명은 너무 길게 넣지 말고, 필요한 곳에 짧게 둔다.

---

## 2. 프로젝트 개요

- 채팅 형식 야근일지를 파싱해 JSON 파일로 저장하는 Windows 단독 앱.
- 직원은 자기 PC에서 입력하고, 데이터는 공유 드라이브 또는 웹하드 폴더에 저장한다.
- 관리자는 데이터 루트 아래 직원별 폴더를 수집해 전체 집계를 확인한다.
- 출퇴근 기록 파일을 읽어 야근일지 누락 여부를 확인한다.
- PyInstaller로 EXE를 만들어 직원 PC에 배포한다.

## 3. 아키텍처

### 백엔드

- `server.py`
  - 로컬 HTTP 서버
  - 설정 저장/로드
  - 폴더 선택 창 호출
  - 브라우저 자동 열기
  - 클라이언트 종료 감지 후 서버 종료
  - API 라우팅

- `service.py`
  - 야근일지 파싱
  - JSON 저장/수정/삭제
  - 데이터 수집
  - 출퇴근 기록 분석
  - 결재 상태 파일 처리
  - 백업/복원/휴지통 처리

### 프론트엔드

- `web/index.html` — 화면 구조
- `web/app.js` — 탭 전환, API 호출, 입력/수정/집계 UI 로직
- `web/styles.css` — 전체 스타일

빌드 도구는 사용하지 않는다. 순수 HTML/CSS/JavaScript로 유지한다.

### 문서

- `README.md` — 사람용 프로젝트 설명
- `SPEC.md` — AI 작업 가이드
- `docs/야근일지_사용설명서.*` — 직원/관리자 배포용 설명서

## 4. 데이터 저장 구조

권장 데이터 루트:

```text
데이터루트
├─ 이호중
│  └─ 야근일지
├─ 박원준
│  └─ 야근일지
└─ 노용주
   └─ 야근일지
```

직원별 저장 구조:

```text
직원이름\야근일지\
  entries\
    YYYY-MM\
      YYYY-MM-DD_HHMM_HHMM_직원이름_xxxxx.json
  backups\
  trash\
  approval_status.json
```

주의:
- 직원명 폴더명과 앱 설정의 이름이 맞아야 한다.
- 관리자가 수집하는 대상은 설정의 `selectedEmployees` 기준이다.
- 직급은 실제 야근일지 JSON이 아니라 설정 파일의 `employeeRanks`에 저장한다.

## 5. 설정 파일

PC별 설정 저장 위치:

```text
%APPDATA%\OvertimeJournal\settings.json
```

주요 설정:

- `employeeName` — 본인 이름
- `dataRoot` — 직원 폴더들이 들어있는 데이터 루트
- `selectedEmployees` — 수집 대상 직원
- `employeeRanks` — 직원별 직급
- `attendanceFolders` — 출퇴근 기록 폴더
- `lateThreshold` — 확인 기준 시간
- `overtimeStart` — 야근 시작 기본 시간
- `hideOldIssues` — 지난달 이전 확인 필요 숨김
- `startupEnabled` — Windows 시작 시 자동 실행
- `theme` — 화면 테마, `dark` 또는 `light`
- `proxyFeatureEnabled` — 대리 입력 UI 표시 여부
- `adminFeatureEnabled` — 직원별 현황/전체 집계 등 관리자 UI 표시 여부

설정 파일에는 회사 실제 데이터나 야근일지 본문을 저장하지 않는다.

## 6. 핵심 업무 흐름

### 직원 입력

1. 설정 탭에서 이름과 데이터 루트 선택
2. 빠른 입력 탭에서 날짜 바로 넣기 또는 야근일지 붙여넣기
3. 미리보기로 파싱 결과 확인
4. 저장
5. 내 현황에서 월별 합계, 달력, 복사/수정/삭제 확인

### 대리 입력

1. 설정에서 대리 입력 기능 사용 켜기
2. 빠른 입력에서 대리 입력 모드 켜기
3. 직원 퇴근 확인 또는 어제 대리 초안 사용
4. 직원 이름 줄 아래에 해당 직원의 야근일지 입력
5. 미리보기 후 저장
6. 대리 수정/삭제 시 이력과 휴지통을 남김

### 관리자 집계

1. 설정에서 관리자 기능 사용 켜기
2. 설정에서 데이터 루트와 수집 직원 체크
3. 필요 시 직급 지정
4. 전체 집계 탭에서 수집
5. 날짜 우선, 직급, 이름, 시작시간 순으로 확인
6. 결재 올림/취소 및 결재 완료 비교
7. 필요 시 CSV 내보내기, 백업/복원

---

## 7. 정렬 규칙

전체 집계와 직원별 현황의 기본 정렬은 다음 순서다.

1. 날짜
2. 직급
3. 이름
4. 시작 시간

직급 순서:

```text
전무 → 상무 → 이사 → 차장 → 과장 → 대리 → 사원
```

직급이 없는 직원은 지정된 직급이 있는 직원 뒤로 정렬한다.

---

## 8. 출퇴근 기록 규칙

- `1`은 출근, `2`는 퇴근으로 처리한다.
- 같은 날짜에 출근을 여러 번 찍으면 가장 빠른 시간을 사용한다.
- 같은 날짜에 퇴근을 여러 번 찍으면 가장 늦은 시간을 사용한다.
- 초는 버리고, 분은 설정된 단위로 반올림한다. 현재 기본은 5분 단위다.
- 퇴근 시간이 확인 기준 이후인데 야근일지가 없으면 확인 필요로 표시한다.

출퇴근 파일 형식은 회사 시스템에 따라 달라질 수 있으므로 파서 변경 전 예시 파일을 반드시 확인한다.

---

## 9. 수정/삭제/백업 원칙

- 수정 시 기존 값과 수정 후 값은 `history`에 남긴다.
- 삭제는 가능한 한 휴지통으로 이동한다.
- 완전 삭제 기능은 관리자 휴지통에서만 다룬다.
- 저장/수정/삭제 시 개인 백업을 유지한다.
- 관리자 백업은 수집 폴더 기준으로 생성한다.

데이터 손실 가능성이 있는 변경은 구현 전에 반드시 백업/복원 흐름을 확인한다.

## 10. 빌드와 배포

개발 실행:

```text
야근일지 실행.bat
```

EXE 빌드:

```text
build_exe.bat
```

수동 빌드:

```text
python -m PyInstaller --noconfirm --noconsole --onefile --name "야근일지" --add-data "web;web" server.py
```

배포:
- 직원에게는 `dist/` 안의 EXE만 전달하면 된다.
- 직원 PC에는 Python, PyInstaller가 필요 없다.
- 설정은 각 PC의 AppData에 저장되므로 EXE를 새 버전으로 교체해도 데이터 루트는 그대로 다시 선택해 사용할 수 있다.

## 11. Git 관리 권장

KOSIS/Local Desk 저장소 안에 함께 두더라도, 이 폴더는 야근일지 단독 앱으로 따로 관리한다.
Local Desk나 KOSIS 작업을 할 때는 이 SPEC을 읽을 필요가 없고, 반대로 야근일지 작업을 할 때는 루트 SPEC보다 이 파일을 우선한다.

소스 저장소에 포함 권장:

- `server.py`
- `service.py`
- `web/`
- `docs/`
- `README.md`
- `SPEC.md`
- `build_exe.bat`
- `야근일지 실행.bat`

Git 제외 권장:

- `build/`
- `dist/`
- `__pycache__/`
- `.edge-print-profile/`
- `*.spec`
- 실제 회사 데이터 루트
- 직원이 작성한 야근일지 JSON
- 회사 출퇴근 원본 파일

PyInstaller가 만든 `.spec` 파일은 현재 운영에서는 Git 제외 대상으로 둔다. 재현 가능한 빌드 설정이 필요해지면 그때 대표 `.spec` 하나만 남기는 방식으로 바꾼다.

## 13. 알려진 주의점

- 회사 공유 드라이브 권한, 경로, 파일명 규칙에 영향을 받는다.
- 직원 폴더명이 실제 직원명과 다르면 수집/출퇴근 매칭이 어긋날 수 있다.
- 출퇴근 기록 파일 형식이 바뀌면 파서도 수정해야 한다.
- EXE 실행 중 브라우저를 닫으면 서버도 종료되는 구조다.
- `dist/`의 EXE는 빌드 결과물이므로 소스와 다르게 취급한다.
